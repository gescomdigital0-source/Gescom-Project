PARTIE 1 · E-MAILS RÉELS
Activer l'envoi réel des e-mails (SMTP)

Depuis leur création, les comptes utilisateurs de GESCOM PROJECT reçoivent un code d'activation à 6 chiffres, puis parfois un code de réinitialisation de mot de passe. Tant qu'aucun serveur d'envoi n'est configuré, la plateforme fonctionne en mode démonstration : le code s'affiche directement à l'écran au lieu de partir dans la boîte mail. Cette partie explique, pas à pas et sans compétence technique particulière, comment brancher un vrai serveur d'envoi pour que chaque code arrive directement dans la boîte mail de l'utilisateur.

1.1 · Comprendre les deux modes d'envoi

Le mode démonstration est celui dans lequel la plateforme se trouve aujourd'hui. À l'inscription, l'écran de vérification affiche le code dans un bandeau et l'administrateur peut le lire dans les journaux du serveur. Ce mode est pratique pour tester l'application sans compte d'envoi, mais il ne convient pas à un usage réel : vos utilisateurs ne reçoivent rien par e-mail.

Le mode réel s'active dès qu'une configuration SMTP complète est enregistrée, soit depuis l'interface d'administration, soit via les variables d'environnement. Le bandeau « mode démonstration » disparaît alors de l'écran de vérification. En mode réel, la sécurité change : le code n'est jamais affiché dans l'application, même en cas d'échec d'envoi — l'utilisateur voit simplement un message l'invitant à réessayer, et seule la configuration d'envoi est à corriger côté administration.

MODE DÉMONSTRATION
Code affiché à l'écran dans un bandeau, aucun envoi réel. Adapté aux tests internes uniquement.
MODE RÉEL
Codes envoyés directement dans la boîte mail de l'utilisateur. E-mail de test disponible avant l'activation.
1.2 · Où saisir la configuration

Connectez-vous avec le compte administrateur (admin@gescom.pro), ouvrez le menu Paramètres puis l'onglet « E-mail ». Un formulaire complet vous attend : serveur SMTP, port et chiffrement, identifiant d'envoi, mot de passe d'application, expéditeur affiché, et un champ d'adresse pour l'e-mail de test. L'onglet contient aussi un rappel des valeurs Gmail et Brevo, exactement celles détaillées ci-dessous.

Conseil important : utilisez d'abord le bouton « Envoyer l'e-mail de test » avant d'enregistrer. Si le test arrive dans votre boîte (vérifiez aussi le dossier spam), vous pouvez enregistrer la configuration en toute confiance. Le mot de passe enregistré n'est jamais réaffiché à l'écran ; pour le changer, resaisissez simplement le nouveau dans le champ prévu.

1.3 · Option A — Gmail (gratuit, rapide, recommandé pour démarrer)

Un compte Gmail gratuit permet d'envoyer environ 500 messages par jour, largement suffisant pour démarrer. Google exige un « mot de passe d'application » à 16 caractères : votre mot de passe Gmail habituel ne fonctionnera pas. Suivez exactement ces étapes :

Créez (ou choisissez) le compte Google d'envoi

Un compte dédié du type no-reply.gescom@gmail.com est recommandé : il sépare clairement les e-mails automatiques d'une boîte personnelle.

Activez la validation en deux étapes

Sur myaccount.google.com/security, activez la validation en deux étapes. Cette activation est obligatoire : Google ne propose les mots de passe d'application qu'aux comptes protégés ainsi.

Créez le mot de passe d'application

Rendez-vous sur myaccount.google.com/apppasswords, nommez-le « GESCOM PROJECT », puis recopiez les 16 caractères affichés (sans espaces).

Saisissez les valeurs dans l'onglet E-mail

Serveur smtp.gmail.com, port 465 (TLS direct), identifiant = votre adresse Gmail complète, mot de passe = le mot de passe d'application, expéditeur affiché = GESCOM PROJECT <votre.adresse@gmail.com>.

Testez, puis enregistrez

Cliquez sur « Envoyer l'e-mail de test », vérifiez la réception (boîte et spam), puis enregistrez la configuration. Le badge « Mode démonstration » disparaît immédiatement.

1.4 · Option B — Brevo (300 e-mails/jour, adapté à la croissance)

Brevo (anciennement Sendinblue) propose une offre gratuite de 300 e-mails par jour et une meilleure délivrabilité à l'échelle, notamment avec un domaine personnalisé. Créez un compte gratuit sur brevo.com, puis dans le menu « Expéditeurs & IP », ajoutez et validez l'adresse expéditrice que vous souhaitez afficher (Brevo exige qu'un expéditeur soit validé avant tout envoi). Ouvrez ensuite « SMTP & API » puis « Clés SMTP » : Brevo affiche vos trois identifiants de connexion SMTP.

Dans l'onglet E-mail de GESCOM PROJECT, saisissez : serveur smtp-relay.brevo.com, port 587 (STARTTLS), identifiant = l'e-mail de votre compte Brevo, mot de passe = votre clé SMTP Brevo. Testez l'envoi, puis enregistrez. Avec un domaine personnalisé, ajoutez les enregistrements SPF et DKIM proposés par Brevo dans votre zone DNS : vos e-mails auront alors bien moins de chances d'arriver en spam.

Quelle option choisir ? Pour tester dès aujourd'hui sans créer de nouveau service, choisissez Gmail (option A). Pour une exploitation durable avec votre propre domaine et une montée en charge, Brevo (option B) est plus adapté. Les deux fonctionnent exactement de la même façon dans la plateforme — et vous pouvez changer d'option à tout moment en resaisissant une nouvelle configuration.
1.5 · Option C — Variables d'environnement (pour l'hébergement)

Sur un serveur ou dans un déploiement automatisé, la configuration peut être fournie par les variables d'environnement plutôt que par l'interface. La configuration enregistrée dans l'interface (base de données) reste prioritaire sur les variables : ainsi, l'administrateur peut toujours ajuster l'envoi depuis l'application sans toucher au serveur. Après toute modification du fichier .env, redémarrez l'application.

# Fichier .env — envoi réel des e-mails (exemple Gmail)
SMTP_HOST=smtp.gmail.com
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=no-reply.gescom@gmail.com
SMTP_PASS=abcd1234efgh5678        ← mot de passe d'application, sans espaces
SMTP_FROM=GESCOM PROJECT <no-reply.gescom@gmail.com>

Tant qu'aucune configuration n'est trouvée (ni interface, ni variables), la plateforme reste volontairement en mode démonstration — l'application ne se bloque jamais, et le parcours d'inscription reste terminable à des fins de test.

PARTIE 2 · DÉPLOIEMENT VERCEL
Déployer GESCOM PROJECT sur Vercel

La plateforme est désormais prête pour Vercel : le build de production est validé, les exports PDF, Word, Excel et PowerPoint fonctionnent côté serveur avec des polices standard (aucun fichier de police à installer), et le code de connexion à la base de données gère automatiquement le double mode « fichier local » ou « base hébergée Turso ». Il ne reste qu'à créer la base, renseigner les variables d'environnement et importer le projet.

2.1 · Ce qui est déjà préparé dans le code
Build de production validé. La compilation Next.js 16 s'achève sans erreur (27 pages générées) ; sur Vercel, le client Prisma est généré automatiquement grâce au script postinstall ajouté au projet.
Adaptateur de base de données intégré. Le fichier src/lib/db.ts bascule automatiquement : tant que DATABASE_URL commence par file:, le SQLite local est utilisé ; dès qu'il commence par libsql://, la connexion passe par l'adaptateur officiel Turso (@prisma/adapter-libsql).
Exports documentaires compatibles cloud. Les PDF utilisent les polices standard Times (intégrées au générateur) : aucun fichier de police à déployer. Les conventions Times New Roman, corps 12, interligne 1,5 et séparateur de milliers « . » restent identiques en production.
Modèle de variables fourni. Le fichier .env.example à la racine du projet documente chaque variable attendue, avec des exemples Gmail et Brevo prêts à copier.
2.2 · Créer la base de données persistante (Turso)

C'est le point technique le plus important : le système de fichiers de Vercel est éphémère. Un fichier SQLite déposé sur Vercel serait recréé à chaque redéploiement et vos données (comptes, projets, documents) seraient perdues à chaque mise à jour. La solution retenue — et déjà branchée dans le code — est Turso, une base hébergée compatible SQLite avec une offre gratuite généreuse :

Créez le compte et la base

Inscrivez-vous sur turso.tech (offre gratuite), puis créez une base nommée gescom depuis le tableau de bord, ou avec la commande turso db create gescom.

Récupérez l'URL et le jeton d'accès

Dans le tableau de bord Turso, ouvrez la base : l'URL ressemble à libsql://gescom-votre-org.turso.io. Créez ensuite un jeton (onglet « Tokens » ou commande turso db tokens create gescom).

Créez les tables dans la base

Générez le script SQL depuis le projet puis appliquez-le à Turso :

npx prisma migrate diff \
  --from-empty --to-schema-datamodel prisma/schema.prisma \
  --script > schema.sql

turso db shell gescom < schema.sql
# ou : collez le contenu de schema.sql dans la console SQL de Turso
Vérifiez la base

Dans la console SQL de Turso, la commande SELECT name FROM sqlite_master WHERE type='table'; doit lister les tables du projet (User, Project, Task, Document…).

2.3 · Mettre en ligne sur Vercel
Poussez le code sur GitHub

Créez un dépôt privé (ex. gescom-project) et poussez le projet. Vercel se synchronisera dessus à chaque mise à jour.

Importez le projet dans Vercel

Sur vercel.com (compte gratuit), « Add New… → Project », autorisez GitHub puis sélectionnez le dépôt. Vercel détecte Next.js automatiquement : laissez la commande de build par défaut.

Ajoutez les variables d'environnement

Dans « Environment Variables », saisissez les variables du tableau 2.4 (au minimum la base de données), puis lancez Deploy. Le premier déploiement prend 2 à 4 minutes.

Vérifiez la mise en ligne

Vercel fournit l'adresse finale https://votre-projet.vercel.app. Ouvrez-la : la page de connexion doit s'afficher, et une inscription de test doit aboutir (voir 2.5).

2.5 · Après le premier déploiement

La base Turso livrée est vide : procédez à l'initialisation dans cet ordre. Créez d'abord le compte administrateur via l'inscription normale (le code d'activation arrive alors par e-mail si le SMTP est déjà configuré, sinon en mode démonstration le temps de la configuration). Ouvrez ensuite Paramètres → E-mail et enregistrez la configuration d'envoi depuis l'environnement de production : l'e-mail de test est alors envoyé avec les mêmes réglages que vos utilisateurs. Enfin, effectuez une inscription complète de bout en bout (création de compte, code reçu par e-mail, création d'un projet, export du dossier) pour valider la chaîne entière.

À noter : les documents générés en production suivent exactement les conventions retenues (Times New Roman, corps 12, interligne 1,5, séparateur de milliers « . »), et le module de validation bloque l'impression définitive des projets non validés, comme en local. Le domaine personnalisé (ex. gescomdigital.services) s'ajoute plus tard dans « Settings → Domains » de Vercel, puis chez votre registrar avec les enregistrements DNS proposés.
